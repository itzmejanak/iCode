# Appearance and Editor Settings — Backend Split Plan

Status: **Appearance/Editor implementation built; palette approval and physical-device acceptance pending** (2026-09-23). This is the first scoped application of the repo-wide [backend splitting rules](./backend-split-rules.md), covering only the application Appearance and Editor Settings pages and the already-connected indent override in Workspace Settings. Terminal, Git, language, runtime, storage, and session restore stay in their own cycles.

> **Note (2026-09-26).** Names in this record are as they were then. The demo layer (`DemoWorkbenchGateway`, `DemoContent`, `staticDemo`, `demo-fork`) was replaced by debug-only capture fixtures (`CaptureGateway`, `CaptureFixtures`, `captureMode`, `capture-fork`) — [code-separation-plan.md](./code-separation-plan.md) K1.

User decisions recorded 2026-09-23: derive Light/AMOLED palettes **for review** rather than treating them as approved; the Appearance slider affects application UI text only and ranges from the current size upward; the current validated layout is **Compact** and turning it off adds room without shrinking touch targets; the fresh-install editor font size is **14 sp**; guarded autosave defaults to **After 1 second**. The candidate palettes are available as visibly labeled previews for review, not frozen product colors.

Implementation ledger (2026-09-23): S1–S4 are wired to one typed `WorkspacePreferencesRepository` and its existing DataStore; new settings persist and apply to current/new Sora views, Markdown, shared Compose tokens, and system bars. S5 has preview Light/AMOLED palettes plus 100–150% UI-only scaling and Compact/comfortable spacing; user palette approval and physical-device accessibility review remain open. S6 uses a per-document debounce, checks the captured revision again inside the gateway, shares the guarded writer with manual Save, writes app-private recovery drafts, prompts to restore/keep disk on reopen, and requires explicit confirmation before a recovered draft overwrites an externally changed file. S7 keeps Format On Save unavailable until a real formatter exists; Settings Root search now finds control terms and opens the existing category page. The obsolete page-local editor settings `Saver` was removed. Unit, build, lint and UI-consistency checks passed; manual device acceptance is still required. This ledger does not claim full session restore, a formatter, or the separate document-recovery center is implemented.

The UI structure and dependency rule come from [ui-split-plan.md](./ui-split-plan.md) §6–7. Product behavior comes from [prd.md](./prd.md) PR-SET-01–07 and PR-EDIT-02, [user-stories.md](./user-stories.md) US-SET-002–004 and US-EDIT-004, [architecture.md](./architecture.md) §10.10, and [layout.md](./layout.md) §4.3, §13.2, §20. ## 2. Scope-specific split rules

Use **one definition, one stored value, one effective value, one consumer adapter** for each setting. This is the backend counterpart of the UI kit rule; it does not mean building a generic settings framework for every future category now.

1. `domain/settings`: immutable typed values, stable IDs, metadata (category, title/description resource, type, default, validator, allowed scope, application effect, availability/restart policy), effective-value resolution, and a repository interface. No Compose, Android `Context`, DataStore keys, Sora, or screen navigation here. Put each setting's validation/default/scope in its definition, not again in UI callbacks.
2. `data/settings`: the **existing** application-private `workspace_settings` DataStore is the only preferences file for this slice. A repository maps stored keys to typed state and writes atomically; it does not know UI controls or editor views. Preserve `editor_indent_size` and existing hashed workspace keys. Extend the current `WorkspacePreferencesRepository` or migrate it behind one compatibility adapter; do not instantiate another DataStore for the same file or make a second source of truth. Do not add Room for these small preferences.
3. `domain/settings` resolver: combine app values and only explicitly scopeable workspace overrides into a read-only effective snapshot. Derived values are never separately persisted. A workspace change re-resolves from the same app state; reset removes only that workspace key. Appearance and the newly planned Editor controls are app-only in this slice; existing indent size and Tab Type remain the only editor workspace overrides until a product rule explicitly expands scope.
4. `designsystem`: immutable semantic palette/typography/density values and a Compose theme provider. It accepts plain appearance values from the composition root but has no dependency on settings storage or screens. The kit reads the provider; screens do not choose raw colors. Keep the approved dark output identical while refactoring. Native views get the same resolved values through narrow adapters, not by reading a Compose local themselves.
5. `ui/editor`: one `EditorSettingsApplier`-equivalent adapter owns Sora setters and TextMate theme changes for all existing and newly created `CodeEditorSession`s. It compares relevant fields before mutating a view. It must not call `setText` for a setting change; tab-switch session identity remains intact. `MarkdownPreview` updates its native view from the same resolved palette and **editor** font size in `AndroidView.update`; the application-UI scale does not resize document content.
6. `data/workspace`: one save coordinator owns explicit save, autosave and any future format-on-save pipeline. It calls the existing `saveDocument`/`DirectFileWorkspaceSource.writeDocument` guard and retains dirty/recovery state on failure. No timer or direct file write belongs in a screen or editor view. Save policy does not change the meaning of close-with-unsaved-changes.
7. `ui/screens/settings`: pages render a settings state (`Loading`, `Ready`, or actionable `Error`) and send typed update intents; they never own a second persisted value in `rememberSaveable`. `rememberSaveable` remains appropriate only for ephemeral form/search/scroll state. Existing `SettingRow`, `Stepper`, `IcodeToggle`, `SegmentedControl`, and swatch visuals stay in the kit/screen as defined by the UI split plan. The registry supplies category/search metadata; search navigates to the *same* control, not a cloned setting page.
8. `demo`: a deterministic in-memory implementation of the same repository contract supplies approved capture values. No `staticDemo` content branch, hard-coded production author/identity, or screen-specific fixture store. Delete page-local demo values only after real and capture paths pass the same screen tests.

Dependency direction: `screen → typed settings contract ← DataStore implementation`; `app root → resolved state → design system / editor adapter`; `save coordinator → existing guarded document writer`. The design system never imports domain or data. A helper is shared only for a second actual consumer or a rule already assigned to the kit. Target small role-based files (about 250 lines each); review larger files for mixed responsibilities rather than splitting mechanically.

Concrete state flow: `workspace_settings DataStore → one repository Flow → confirmed AppSettings + workspace overrides → effective resolver → IcodeApp → IcodeTheme / CodeEditorSessions / save coordinator`. `AppearanceScreen` and `EditorSettingsScreen` read that confirmed state and send updates back to the same repository. Today `IcodeTheme` wraps `IcodeApp` **before** the repository is collected; move collection/construction above the theme provider in one controlled composition-root step, keeping the existing `staticDemo` repository choice and a stable approved-Dark loading state. Do not instantiate a new repository inside each settings page.

## 3. Minimal contract and key ledger

Do not place one mutable “settings” map in the UI. Proposed types are `AppearanceSettings`, `EditorSettings`, `WorkspaceEditorOverrides`, `EffectiveEditorSettings`, `SettingsLoadState`, and a small typed definition/catalog for metadata and validation. One canonical app snapshot owns the existing `editor_indent_size`; while old callers still use `WorkspacePreferences`, make that object a **projection** of the new snapshot, not an independently loaded or writable copy. Repository operations expose a `Flow` of confirmed state and report invalid/write failures to the initiating page; never optimistically show a failed value as saved. Explicitly rethrow coroutine cancellation instead of turning it into a settings error. The catalog may drive titles, search, reset text and validation, but **not** generate a replacement screen layout.

| Stable ID / key | Scope | Default or decision gate | Consumer |
|---|---|---|---|
| `appearance.theme` | app | Approved Dark; Light/AMOLED gated on palette approval | Theme provider + native color adapters |
| `appearance.ui_scale` | app | UI chrome text only; current rendering = 100%, upward only; proposed 100–150% in 5% steps, gated by layout/accessibility QA | UI typography tokens, not editor/Markdown/terminal |
| `appearance.compact_layout` | app | On = current validated metrics; Off = more spacious token map to review | Shared density/spacing tokens |
| `editor.font_size_sp` | app | **14 sp** fresh-install default by user decision; replaces actual Sora 13 sp initialization | Sora base font size; Markdown preview follows editor size |
| `editor.font_family` | app | IBM Plex Mono per `layout.md` §4.3; system monospace only as fallback | Sora font adapter |
| `editor_indent_size` | app, existing key | **4, already real** | Existing effective-indent resolver and Sora |
| existing hashed workspace indent/type keys | workspace, existing keys | `null` means inherit | Existing resolver and Sora |
| `editor.word_wrap` | app | On in the current Sora and settings frame | Sora `setWordwrap` |
| `editor.line_numbers` | app | On in the settings frame; verify native initial state | Sora `setLineNumberEnabled` |
| `editor.bracket_matching` | app | On in the settings frame; verify native initial state | Sora `setHighlightBracketPair` |
| `editor.auto_save` | app | After 1 second once guarded pipeline ships; Off and proposed After 5 seconds selectable | Save coordinator |
| `editor.format_on_save` | app | Unavailable until formatter exists; no implied success | Save coordinator + formatter capability |
| `editor.minimap` | app | Off on compact screens per layout §13.2; experimental library device-QA gate | Sora `props.showMinimap` |

The dotted IDs above are contract proposals, **not existing stored keys**. During implementation, freeze each storage key in a single key-mapping file and add migration tests before release. Do not write settings into project files. Keep Git identity in Git config, not in this app preference store.

## 4. Lifecycle and failure contract

1. **Cold start / process restart:** create the one repository at application scope; load app values before choosing theme and then resolve workspace overrides. Show the approved dark appearance during loading to prevent a false Light/AMOLED flash. Once loaded, all consumers receive the same immutable snapshot. Do not silently treat DataStore read failure as “saved defaults”; show recovery/error and block writes until the state is known. Existing invalid individual values may fall back through their validated definition with a visible repair path, without resetting unrelated keys.
2. **Edit / switch scope:** validate at the domain boundary, write transactionally, emit the new snapshot, update the page and consumers. A workspace switch changes only eligible overrides. Reset-to-Inherited deletes a key rather than writing the current app value. An invalid setting or failed write retains the last confirmed value and displays feedback.
3. **Open/switch/close tabs:** apply settings to existing and future per-document Sora sessions via the installed APIs: `setTextSize`, `setTypefaceText`, `setWordwrap`, `setLineNumberEnabled`, `setHighlightBracketPair`, existing `setTabWidth`, and—after experimental QA—`props.showMinimap`. A visual setting change cannot replace document text, dirty flags, undo history, selection, caret, scroll or fold state. Pinch zoom is a transient per-session interaction until a persistence rule is decided; unrelated setting emissions must not call `setTextSize` and reset it. Terminal font size remains separate.
4. **Edit and save:** debounce by document/revision; cancel stale pending jobs, but do not cancel a file write mid-commit. Serialize saves per document; recheck current revision, read-only state, workspace identity and expected external fingerprint at write time. Route manual and automatic saves through the same path, keep dirty on error, integrate and retain the recovery draft, and provide visible status without a toast on every autosave (`DocumentSaved` currently triggers a toast for every save). A new edit during a save stays dirty until its own revision is saved. The existing fingerprint check is read-before-replace, not atomic compare-and-swap; test the external-writer race and preserve a recoverable draft/explicit conflict instead of claiming perfect overwrite prevention. Coordinate with the separate external-change/recovery owner before S6.
5. **Format-on-save:** first inspect whether the installed Sora language has a real configured `Formatter`; if not, use a language server's advertised formatting capability when that subsystem lands. Define whether formatting occurs before disk write, how a stale response is discarded, and how one user-visible undo step is preserved. A missing/failed formatter must not claim formatted success or block an ordinary save without an explicit product rule.
6. **Theme changes:** update semantic Compose colors, Material, Sora/TextMate syntax and decorations, Markdown preview, terminal palette and system bars together or gate a theme until all required consumers are ready. Verify Git/diff/conflict/diagnostic distinguishability and readable focus/selection states. Do not alter source text or syntax scope while recoloring.
7. **Migration/corruption:** preserve existing `editor_indent_size` and hashed workspace override/Auto-Fetch keys. Version any renamed/new schema; keep unknown future keys untouched. Test an existing-install upgrade, invalid enum/range, missing/deleted workspace, DataStore I/O failure and corrupt bytes. Recovery must be explicit and non-destructive; never erase all settings silently to hide corruption.

## 6. Acceptance and unresolved decisions

- One stored source and one effective value at a time; app setting edits appear everywhere they apply, survive restart and do not alter another workspace's overrides.
- Existing UI controls remain visually consistent with the 40-frame reference; disabled controls explain why, and no control claims an unavailable capability.
- Theme/typography changes reach Compose and embedded native views; dark fidelity, accessibility text scale, 48 dp targets, Git/diff/diagnostics contrast and compact/expanded layouts are verified.
- Editor changes preserve two dirty tabs, source bytes until save, undo/selection/scroll, Markdown rendering and two-finger zoom. Autosave never bypasses the external-change guard.
- The regression suite includes registry uniqueness, validation, migration, resolution, failure, adapter idempotence and save races; later per-frame cleanup follows [integration-plan.md](./integration-plan.md) §5 and §10.

**Still to settle at the relevant gates:** user approval/revision of candidate Light/AMOLED palettes; physical-device review of the implemented 100–150% UI-text range and comfortable spacing; whether a reopened tab restores transient pinch zoom; formatter source and failure policy. Already settled and implemented: 14 sp editor initial size, UI-only text scaling, independent terminal font, IBM Plex Mono, and guarded fresh-install After 1 second autosave. Minimap uses Sora's experimental property and still needs compact-device review; it is not a hand-built second renderer.

Library checks: [Android custom design systems](https://developer.android.com/develop/ui/compose/designsystems/custom) supports immutable theme values via a provider around Material; [Android DataStore](https://developer.android.com/topic/libraries/architecture/datastore) requires one instance per file per process; [Sora releases](https://github.com/Rosemoe/sora-editor/releases) label the 0.24.5 minimap experimental and note a 0.24.6 minimap-region change. The installed dependency is Sora 0.24.6; API/device behavior still needs verification.
